## 1. 两个脚本共用的四个工具函数

### 1.1 `multibandread` / `multibandwrite`（`compressor.py:21-55`，`decompressor.py:21-55`）

```python
21  def multibandread(fname,shape,dtype,offset,interleave):
27          if interleave == 'BIL':
28              for i in range(shape[0]):
29                  for j in range(shape[2]):
30                      f.seek(offset + (i + j*shape[0])*shape[1]*dtype.itemsize)
31                      data[i,:,j] = np.fromfile(f, dtype=dtype, count=shape[1])
33          if interleave == 'BSQ':
34              for i in range(shape[2]):
35                  f.seek(offset + i*shape[0]*shape[1]*dtype.itemsize)
36                  data[:,:,i] = np.fromfile(f, dtype=dtype, count=shape[0]*shape[1]).reshape(shape[0],shape[1])
```

- 这是 MATLAB `multibandread` 的 Python 复刻，用来读写**裸格式**高光谱数据。
  - **BSQ**（Band Sequential）：一个波段一个波段连续存放 ⇒ 第 i 个波段整体 seek 一次；
  - **BIL**（Band Interleaved by Line）：一行内的所有波段连续存放 ⇒ 逐行 seek。
- `shape` 在调用处一律是 `(N_rows, N_cols, N_bands)`，即 **(行, 列, 波段)**，
  与网络内部的 `(T, C, I)` 完全一致（见 `00-总览.md` 的符号表）。
- `multibandwrite` 是它的逆操作，`data[i,:,j].tofile(f)` 直接按 C 连续写。

> README 明确要求：“Compression tests require image files to be provided as **raw files
> with BSQ ordering, little-endian 16-bit unsigned integers**.” 这里就是那个约定的实现。

### 1.2 `map_error` / `unmap_error`（`compressor.py:59-65`，`decompressor.py:59-74`）

```python
59  def map_error(e):
61      em = e+0
62      em[e>=0] = e[e>=0]*2
63      em[e<0] = np.abs(e[e<0]*2+1)
64      return em

68  def unmap_error(em):
70      e = em+0
71      e[em%2==0] = em[em%2==0]/2
72      e[em%2==1] = -(em[em%2==1]+1)/2
73      return e
```

- 这是 CCSDS-123.0-B-2 的 **“positive mapping”（ZigZag 映射）**：
  `0→0, −1→1, 1→2, −2→3, 2→4, …`，把有符号残差变成非负整数，
  以便喂给只能处理非负符号的自适应 Golomb 编码器。
- 论文 Sec. III-A 原话：
  > “In this work, we use the **sample-adaptive Golomb encoder defined by the
  > CCSDS-123.0-B-2 standard [22]** as entropy coder for the **positive-mapped prediction
  > residuals** to ensure fair comparisons with the CCSDS predictor.”

- `decompressor.py:71-72` 用浮点除法（`/2`），所以解出来的 `residuals` 是 float32；
  因为输入保证是整数，结果仍然精确。

### 2.3 逐行归一化与边信息（113–127）★论文没有的部分

```python
114     with torch.no_grad():
116         quant_step_size = (2*param.delta_quantization+1)
118         mu_subfactor = 16
121         mu_enc = torch.round( torch.mean(data[:,::mu_subfactor],dim=(2,),keepdim=True) ) # (1,T,1,I)
122         mu =  torch.repeat_interleave( mu_enc / quant_step_size , mu_subfactor, dim=1 )
123         sigma_enc = torch.round( torch.std(data[:,::mu_subfactor],dim=(2,),keepdim=True) ) # (1,T,1,I)
124         sigma = torch.repeat_interleave( sigma_enc / quant_step_size + 1e-8 , mu_subfactor, dim=1 )
126         data = torch.round(data/quant_step_size)
127         data = (data-mu)/sigma # (1,T,C,I)
```

- **121 / 123**：`data[:, ::16]` 表示**每隔 16 行采样一行**，再沿**列**方向（`dim=2`）
  求均值和标准差。所以 μ、σ 的形状是 `(1, T/16, 1, I)`：
  **每一行采样点、每一个波段一个标量**。
  采样是为了节省边信息体积（`mu_subfactor = 16` 是精度/开销的折中，
  代码里还留着 `=10`、`=1` 的注释供试验）。
- **122 / 124**：`repeat_interleave(..., 16, dim=1)` 把采样值复制回完整的 T 行
  ——即**分段常数近似**：第 0–15 行用第 0 行的统计量，第 16–31 行用第 16 行的，依此类推。
  `sigma` 额外 `+1e-8` 防止除零（纯黑波段会出问题）。
- **121–124 的顺序说明**：μ、σ 是在**原始（未量化）**的 `data` 上算的，
  而且除以 `quant_step_size` 后正好与第 126 行量化后的数值同尺度。
  即 `Iq_normalized = (Iq − μ_int)/σ_int`。
- **126–127**：先量化再归一化。**论文 Sec. III-A 只说了 `I^q = round(I/Q)`，
  这里多出来的归一化是纯工程实现**（原因：16-bit 动态范围直接喂网络很难训）。

> **为什么 μ/σ 可以逐行算而不破坏因果性？**
> 因为“一整行”（全部列）在推扫成像里是同时到手的原子数据单元，
> 详见 `02-模型-model.py.md` 第 1 节对编码器非因果卷积的解释。

### 2.4 第一行与第一波段：DPCM（130–155）↔ 论文 Sec. III-F

论文 Sec. III-F（p.6）：

> “In order to ensure causality of the model, **the first line for all bands and the entire
> first band need to be compressed with a separate method**. For the first line, we use a
> simple **differential pulse coded modulation (DPCM)** encoder where the prediction error is
> computed as
> E_{0,x,z} = I^q_{0,0,0}, for x = 0, z = 0
> E_{0,x,z} = I^q_{0,x,0} − I^q_{0,x−1,0}, for x > 0, z = 0
> E_{0,x,z} = I^q_{0,x,z} − I^q_{0,x,z−1}, for x ≥ 0, z > 0.”

```python
132     # Encode first line for all bands
133     quantized_residuals[0,0,0] = data[0,0,0,0]*sigma[0,0,0,0]+mu[0,0,0,0]
134     for band_no in range(data.shape[3]):
135         if band_no == 0:
136             #dpcm over cols
137             first_lines_rec = torch.zeros(data.shape[2],data.shape[3], device=config.device) # (C,I)
138             first_lines_rec[0,0] = data[0,0,0,0]*sigma[0,0,0,band_no]+mu[0,0,0,band_no]
139             for col_no in range(data.shape[2]-1):
140                 pred = torch.round(first_lines_rec[col_no,0])
141                 res = data[0,0,col_no+1,0]*sigma[0,0,0,band_no]+mu[0,0,0,band_no] - first_lines_rec[col_no,0]
142                 quantized_residuals[0,col_no+1,0] = torch.round(res)
143                 first_lines_rec[col_no+1,0] = pred + quantized_residuals[0,col_no+1,0]
144         else:
145             #dpcm over bands
146             pred = torch.round(first_lines_rec[:,band_no-1]) # (C,)
147             res = data[0,0,:,band_no]*sigma[0,0,0,band_no]+mu[0,0,0,band_no] - first_lines_rec[:,band_no-1]
148             quantized_residuals[0,:,band_no] = torch.round(res)
149             first_lines_rec[:,band_no] = pred + quantized_residuals[0,:,band_no]
```

- **133**：`x=0,z=0` 的残差就是像素本身（`data*σ+μ` 把归一化值还原成量化后的整数）
  ⇒ 论文第一行的 `E = I^q_{0,0,0}`。
- **139–143**：`z=0` 时沿**列**方向 DPCM：预测 = 左邻像素，残差 = 当前 − 左邻
  ⇒ 论文的第二个式子。`res` 里用的是**未取整的** `first_lines_rec`，
  但由于它始终是整数累加（`pred` 取整 + 整数残差），`round` 实际不改变数值。
- **145–149**：`z>0` 时沿**波段**方向 DPCM：预测 = 前一个波段同列像素
  ⇒ 论文的第三个式子。这是**跨波段相关性远强于跨列相关性**这一先验的最直接利用。
- **153–155**：把重建出的第一行存进 `data_rec`，并归一化成 `(1,1,C,I)` 供编码器使用。

```python
153     C,I = first_lines_rec.shape
154     data_rec[0,0,:,:] = first_lines_rec
155     first_lines_rec = (first_lines_rec.unsqueeze(0).unsqueeze(0) - mu[0,0,:,:])/sigma[0,0,:,:] # (1,1,C,I)
```

- **155**：用**第 0 行的 μ/σ**归一化（与后面逐行处理时一致）。

### 2.5 主循环（160–200）—— Algorithm 1 的逐行落地

论文 Alg. 1（p.4）：

> **Require:** Prequantized image I^q = round(I/Q)
> **Require:** Init u_{−1,x,z} = 0 ∀x,z
> **Require:** Init states a_{−1,x,z}, b_{−1,x,z} = 0 ∀x,z
> Compress first line (Section III-F) to get E_{0,x,z} ∀x,z
> **for** y = 1, … **do**
> 　u_{y−1,x,z} ← Encoder(I^q_{y−1,:,z}) ∀x,z
> 　û_{y,x,z}, (a,b)_{y−1,x,z} ← LinePredictor(u_{y−1,x,z}, u_{y−2,x,z}, a_{y−2,x,z}, b_{y−2,x,z}) ∀x,z
> 　E_{y,x,0} = Decoder₀(û_{y,x,0}) − I^q_{y,x,0} ∀x
> 　Π_{y,x,z−1} = u_{y,x,z−1} − û_{y,x,z−1} ∀x, z ≥ 1
> 　Π̂_{y,x,z} = SpectralPredictor({Π_{y,x,ζ}}_{ζ<z}) ∀x, z ≥ 1
> 　Î^q_{y,x,z} = Decoder(Π̂_{y,x,z} + û_{y,x,z}) ∀x, z ≥ 1
> 　E_{y,x,z} = Î^q_{y,x,z} − I^q_{y,x,z} ∀x, z ≥ 1
> **end for**

```python
160     for line_no in range(data.shape[1]-1):
162         # encode first line
163         if line_no == 0:
164             a = model_encoder(first_lines_rec)[:,0,:,:,:] # (1,F,C,I)
166         # spatial prediction
167         x_spatial = model_spatial_rnn(a) # (C,I,F)
```

- **160**：`range(H-1)` ⇒ 用第 `line_no` 行（及其过去）预测第 `line_no+1` 行，
  完全对应 Alg. 1 的 `for y = 1, …`。
- **163–164**：第一次进入循环时，把**重建后的第 0 行归一化特征**编码
  ⇒ Alg. 1 的 `u_{y−1} ← Encoder(I^q_{y−1,:,z})`，此处 `y−1 = 0`。
  **后续迭代不再重复编码**，因为上一轮结尾已经把当前行的特征算好并放进了 `a`
  （见第 200 行）——这就是为什么 `a` 同时充当“这一轮的 u_y”和“下一轮的 u_{y−1}”。
- **167**：**递归线预测器**。它内部持有跨行状态 `state_lines`，
  输入 `a`（上一行特征的编码），输出 `x_spatial` = û（对当前行的特征预测）
  ⇒ Alg. 1 的 `û_{y,x,z}, (a,b) ← LinePredictor(...)`。

#### band 0 分支（169–180）

```python

```

- **170**：`(1,F,C,I) → (C,I,F)`，把 F 放到最后一维，方便按波段切片。
- **171–173**：`E_{y,x,0} = Decoder₀(û_{y,x,0}) + 上一行同列 band0 − I^q_{y,x,0}` 的
  **预测值**部分。注意 **172 行用上一行的 μ/σ 归一化，173 行用当前行的 μ/σ 反归一化**
  ——因为跳连项的物理含义是“上一行那个像素的亮度”，
  而它要在当前行的归一化坐标系里使用，必须转两次。
  这条跳连论文没写（见 `00-总览.md` 差异清单第 3 条）。
- **174–177 数值告警机制**（论文 Sec. III-E）：
  - 如果 `|round(v) − v| > 0.5 − 1e-3`，说明这个浮点值**离舍入判决边界不到 1e-3**，
    FP32 精度差异可能导致压缩端/解压端取到不同的整数；
  - 此时 `pos_numerical_warning = 1`，**改用 `floor`**（永远向下取整），
    并把这一位存下来传给解码端。
  论文原话：
  > “whenever the prediction is closer to the rounding threshold than 10⁻³ (in unnormalized
  > integer digital numbers), we **signal the side of the threshold** as extra information.
  > … The side information is entropy-coded and, in our tests, incurred a small penalty of
  > **0.02 bpppc**, which is already included in all experimental results.”

  “signaling the side of the threshold” = 告诉解码端“这一位该往下取还是往上取”，
  代码用 `floor` + 一个 bit 实现。
- **178 `clamp(-16383, 16383)`**：把预测值限制在 14-bit 范围。
  因为残差最终要以 uint16 存储（ZigZag 后 `±16383 → [0, 32767]`），
  且熵编码器用 `--u_max 18`（18 位动态范围）配置。
  **这个 clamp 是解码端必须复现的关键步骤**，否则会错位。
- **179–180**：`E = I^q − round(Î)`，然后 `data_rec = round(Î) + E = I^q`
  ⇒ **无损**（残差本身就承载了全部信息），这正是论文说的
  “prequantization … then using **lossless prediction**”。

- **183 `a_tmp`**：对**当前要预测的行**（`line_no+1`）做编码，得到 Alg. 1 里的 `u_y`。
  ⚠️ 注意这里用的是 `data`（原始预量化图），**不是 `data_rec`**。这正是论文
  Sec. III-A 对“预量化”的解释：

  > “On the other hand, prequantization consists of quantizing the input image and then
  > using lossless prediction. **This avoids data dependencies at the compressor since there
  > is no discrepancy between the original pixel value and the value to be used for
  > prediction**, so it leads to **higher compression throughput**.”

  因为残差是无损编码的，`data_rec` 与 `data` **逐比特相同**，
  所以压缩端可以放心用原图、避免串行依赖；而解压端必须用重建值
  （`decompressor.py:186/202`），这也是解压端被迫逐波段串行的根本原因。
- **187**：`delta = Π̂`（并行谱预测器一次算完所有波段）。
- **190**：`decoder(û_{z≥1}, Π̂ 左移一位)`。
  - `x_spatial[:,1:,:]` = 波段 1…I−1 的线预测特征；
  - `delta[:,:-1,:]` = 波段 0…I−2 的谱预测输出。
  两者对齐后，**预测波段 z 时用到的谱信息只来自波段 < z** ⇒ 严格因果
  （对应 Fig. 2 中 `Δ̂_{z−1}` 的箭头）。
- **191–196**：反归一化 → 舍入（含数值告警）→ clamp，与 band 0 分支同样的三步。
- **197–198**：残差与重建。

```python
200         a = torch.permute(torch.reshape(a,[1,C,I,config.dim_enc]),[0,3,1,2]) # (C,I,F) --> (1,C,I,F) --> (1,F,C,I)
```

- **200**：把 `a` 还原成 `(1,F,C,I)`，供**下一次迭代**的 `model_spatial_rnn(a)` 使用。
  循环结束时，`a` 里装的就是本行（`line_no+1`）的特征 ⇒ 下一轮它就是“上一行的 u”。

  **这一行是整段代码最容易被忽略、但决定正确性的地方**：
  线预测器的输入序列必须是 `u_{y−1}, u_{y−2}, …`，而这里保证了递归链条不断。

- **223–227**：σ 完全对称处理。
- **229–231**：把**未压缩的浮点 μ/σ** 也写进 H5（`side_info_file`）——见第 6 节的注意事项。

## 3. `decompressor.py` 逐段讲解

解压整体是压缩的镜像，但**有三处必须不同**，正是这三处决定了它能不能跑。

### 3.1 读边信息与残差（103–122）

### 3.3 主循环（162–203）—— 与压缩端的三处关键差异

```python
162     for line_no in range(data_rec.shape[0]-1):
164         # reset spectral state
165         model_spectral_rnn.reset_state()
167         # encode first line
168         if line_no == 0:
```

**差异 ①：每行开头必须 `reset_state()`。**
波段方向的 RWKV 递归只在一行内部有效；跨行重置，跨行的记忆完全由
`model_spatial_rnn.state_lines` 承担。压缩端用并行谱预测器，天然没有跨行状态问题。

**差异 ②：`next_line_hat` 显式保存“上一行的归一化重建值”。**
`compressor.py` 直接用 `data_rec[line_no]`（原始真值），解压端只能用重建值。
它在每次迭代末尾被更新为刚解出的那一行（第 185、201 行）。

```python

176         a = torch.reshape(a.permute((0,2,1,3)),[C,I,config.dim_enc]) # (C,I,F)
177         predicted_value = model_bandzero_decoder(x_spatial[:,0:1,:])
178         predicted_value = predicted_value[:,0,0] + next_line_hat[0,0,:,0] # (C,)

186         a_tmp = model_encoder(next_line_hat[:,:,:,0:1])[:,0,:,:,:] # (1,F,C,1)
```

- **177–178**：band 0 的预测 = `Decoder₀(û) + 上一行 band0（归一化）`，
  与压缩端 171–173 行、训练端 `model.py:405-407` 三处一致。
- **180–181**：**必须复现压缩端的 `floor`/`round` 判决与 clamp**，
  否则预测值差 1，残差就对不上。这正是 FP32 数值误差会毁掉无损解码的地方，
  `numerical_warning` 位就是为此而传。
- **183**：`data_rec = round(Î) + E`。
- **185**：把刚解出的像素**归一化后存进 `next_line_hat`**，供
  ① 下一行的 band-0 跳连（第 178 行），② 本行后续波段的特征编码（186–187 行）。
- **186–187**：**差异 ③ 的第一半**——用**刚解码出的那一个波段**（`...0:1`）
  单独做一次编码，只填充 `a[:,0,:]`。

```python

190         for band_no in range(I-1):

196             predicted_value = ((1-numerical_warning[line_no,:,band_no+1])*torch.round(predicted_value) + numerical_warning[line_no,:,band_no+1]*torch.floor(predicted_value)).type(torch.float32)
197             predicted_value = torch.clamp(predicted_value,-16383,16383)
199             data_rec[line_no+1,:,band_no+1] = predicted_value + residuals[0,line_no+1,:,band_no+1]
201             next_line_hat[0,0,:,band_no+1] = (data_rec[line_no+1,:,band_no+1] - mu[0,line_no+1,:,band_no+1]) / sigma[0,line_no+1,:,band_no+1]

203             a[:,band_no+1,:] = torch.reshape(torch.permute(a_tmp,[0,2,3,1]),[C,1,config.dim_enc])[:,0,:] # (C,F)
```

**差异 ③ 的第二半：逐波段串行。** 这段 12 行是理解解压端复杂度的核心：

- **192**：`delta = spectral_rnn(a[:,z,:], x_spatial[:,z,:])`。
  `a[:,z,:]` 是**第 z 个波段刚被编码出来的特征**（第 202–203 行填进去的），
  `x_spatial[:,z,:]` 是线预测器对该波段的预测 ⇒ 内部算出 `Π_z = u_z − û_z`（Eq. 11）
  并推进波段递归状态。
- **194**：用 `delta`（即 `Π̂`，由 `Π_{<z+1}` 推出）和 `x_spatial[:,z+1,:]`（û）
  解码第 `z+1` 个波段。
- **199–203**：解码 → 反归一化 → 写入 `data_rec` → 更新 `next_line_hat` →
  **立刻把该波段重新编码成特征填回 `a`**，供下一个波段使用。

  ⇒ 这正是论文 Sec. III-D 那句警告的实现：
  > “Notice that Π_{y,x,z} **requires pixel I^q_{y,x,z}** for its computation. Therefore,
  > this **needs to have been already decoded**, and its availability is ensured by treating
  > the first band as a special case.”

- **循环次数是 `I−1` 而不是 `I`**：因为 band 0 在 176–187 行已经处理完，
  这里只负责波段 1…I−1。
- **205**：把 `a` 还原成 `(1,F,C,I)`，供下一行的 `model_spatial_rnn(a)` 使用
  （与压缩端第 200 行完全对称）。

## 4. 压缩端 vs 解压端 对称性总表

| 环节 | `compressor.py` | `decompressor.py` | 是否必须一致 |
|---|---|---|---|
| 量化步长 | `2*delta+1` | 同名参数 | ✅ 必须一致 |
| μ/σ | 从原图算，写 H5 + `.cmp` | 从 H5 读 | ✅ 必须一致 |
| 第一行 DPCM | 132–149 编码 | 134–153 解码 | ✅ 严格镜像 |
| 线预测器状态 | 常驻不重置 | 常驻不重置 | ✅ |
| 谱预测器 | **并行**（CUDA） | **递归**（手写，每行 reset） | ⚠️ 数学等价、数值可能有差 |
| band 0 的跳连 | 用 `data_rec[line_no]` | 用 `next_line_hat` | ✅ 值相同（无损） |
| 特征 `a` 的来源 | **原图** `data` | **重建图** `next_line_hat` | ⚠️ 仅因无损残差才等价 |
| 舍入 + clamp | round/floor + ±16383 | 完全相同 | ✅ 必须逐位一致 |
| 残差 | 写 `.bsq` → 编码为 `.cmp` | `.cmp` → 解码为 `.bsq` | ✅ |
| 数值告警 | 编码 | 解码 | ✅ |
| 重建图输出 | `Iq*Q` 存 `.mat` | `Iq*Q` 存 `.mat` | ✅ |

## 6. 两个必须知道的工程细节（复现时容易踩坑）

### 6.1 μ/σ 存在两份，码率只算其中一份

`compressor.py` 同时产出：

- `side_info.h5`：**浮点** μ/σ（`h5py`，`(1,T,1,I)`，`compressor.py:229-231`）；
- `side_info.h5_mu.cmp` / `_sigma.cmp`：**整数** `mu_enc/sigma_enc` 的一阶差分
  经 ZigZag + Golomb 编码的结果（`compressor.py:217-227`）。

而 `launcher_compress.sh` 统计码率时用的是：

```bash
ratecmp=`wc -c $compressed_file`
ratenum=`wc -c $numerical_warning_file`
rateside0=$(( 64*$N_bands ))
ratesidemu=`wc -c $side_info_file_mu`
ratesidesigma=`wc -c $side_info_file_sigma`
rate=$(( $ratecmp+$ratenum+$rateside ))
```

⇒ **`.h5` 本身没有计入码率**，真正计价的是 `mu/sigma` 的压缩版本。
由于 `mu = repeat_interleave(mu_enc/Q, 16)`，两者信息完全等价，
所以这个统计在信息论意义上是自洽的；但 `decompressor.py` 目前**只读 `.h5`**，
如果要做严格的“只依赖码流的解码器”，需要自己从 `_mu.cmp/_sigma.cmp` 反推 μ/σ。

另外脚本里还有一项固定开销 `64*N_bands` 字节（128×202 图约 12.9 KB），
从代码本身看不出它精确对应哪份数据，作者应该是用它近似某类未单独落盘的边信息。

### 6.2 数值告警的码率占比 = 论文说的 0.02 bpppc

`numerical_warning` 的形状是 `(T−1, C, I)`，即**每个像素一个 bit**（但极稀疏，
真正为 1 的极少）。以 128×128×202 为例，理论最多
`127×128×202 = 3,284,672` bit ≈ 401 KB；由于 CDF 假设 `P(1)=1e-3`，
实际压缩后只有几 KB 量级，折算 bpppc 正好落在这句话上：

> “The side information is entropy-coded and, in our tests, incurred a **small penalty of
> 0.02 bpppc**, which is already included in all experimental results.”

这也是为什么 `launcher_compress.sh` 会把 `ratenum` 单独列出来累加。
