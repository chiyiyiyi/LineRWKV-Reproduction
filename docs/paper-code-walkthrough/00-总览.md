## 1. 一句话概括：这个仓库到底在做什么

论文的原话（p.3, Sec. III-A）：

> “This is a predictive coding method, where a pixel is predicted from a causal spatial and
> spectral context, and only the prediction error is encoded. The method comprises a
> prequantizer to introduce losses, followed by a deep-learning-based predictor, called
> LineRWKV, and an entropy encoder to code the prediction residuals.”

也就是说，整个系统只有三件事：

1. **预量化**：`I^q = round(I / Q)`，Q 为奇数（代码里 `Q = 2*delta+1`）。Q=1 时退化为无损。
2. **神经网络预测**：LineRWKV 逐行（line by line）预测每个像素，输出预测值 `Î`。
3. **熵编码残差**：只把 `E = Î − I^q`（实际是四舍五入后的整数残差）送去熵编码。

代码里这三件事分别落在 `compressor.py`（第 116–198 行）、`model.py` / `inference.py`
（网络本体）、以及外部的 CCSDS-123.0-B-2 自适应 Golomb 编码器二进制
（`Code/compressor`、`Code/decompressor`）。

## 3. 系统数据流（把 Fig. 1 / Fig. 2 / Algorithm 1 合成一张图）

压缩端（`compressor.py`）：

```
raw I (uint16 BSQ)
   │  ① 预量化 Q = 2δ+1 ; Iq = round(I/Q)
   ▼
每行 (line y-1) ──► LineEncoder ──► a  (特征, 全体波段 × 全列)
                                      │
                                      ▼
                            LineRWKV_RNN_spatial (行间递归 RWKV, 状态常驻)
                                      │  û_y  ← 对第 y 行特征的预测
                                      ▼
第 y 行真值 ──► LineEncoder ──► u_y ──(-)──► Π = u_y − û_y
                                              │
                                              ▼
                            LineRWKV_RNN_spectral_parallel (波段间 RWKV)
                                              │  Π̂_z
                                              ▼
                          LineDecoder( û_y,z + Π̂_z ) ──► 标量像素预测 Î
                                              │
                          E = round(Î) − I^q ─┘ ──► zigzag 映射 ──► CCSDS Golomb 熵编码
```

解压端（`decompressor.py`）与压缩端**唯一的本质差别**：波段必须**逐个解码**，因为
`Π_z = u_z − û_z` 依赖第 y 行第 z 波段那个**刚被解码出来**的像素（论文 p.6 原话：
“Notice that Π_{y,x,z} requires pixel I^q_{y,x,z} for its computation. Therefore, this needs
to have been already decoded”）。所以：

- 压缩端可以用 **并行（parallel）** 的 RWKV 一次性算完所有波段（`LineRWKV_RNN_spectral_parallel`）；
- 解压端只能用 **递归（recurrent）** 的 RWKV 逐波段推进（`LineRWKV_RNN_spectral`），
  并在每行开始时 `reset_state()`。

论文 Sec. III-D 也明确写了这个分工：

> “for a lossless (or prequantized) compressor, the parallel implementation typically
> reserved for training is used rather than the recurrent implementation described in
> Section III-C in order to ensure high throughput.”

## 5. 代码与论文的差异清单（先看这张表，能省掉大量困惑）

下面是通读代码后发现的、论文里**没有写**或**写法不同**的地方。这些不是 bug，多数是
工程实现细节，但直接决定了你能不能复现实验。

1. **逐行归一化 + 边信息传输（论文完全没提）**
   代码在进入网络前做 `x = (x − μ) / σ`，其中 μ、σ 是**每一行、每一波段**沿列方向的
   均值/标准差（`compressor.py:118-127`）。μ、σ 每 16 行采样一次并重复插值填充
   （`mu_subfactor = 16`），量化成整数后差分、熵编码成边信息文件
   （`compressor.py:216-231`）。解压端再从 `side_info.h5` 读回来
   （`decompressor.py:119-122`）。论文 Sec. III-E 只说了 “The predicted pixel value is
   then denormalized”，没有描述这套机制。
2. **训练用整块统计量，推理用逐行统计量（train/test 不一致）**
   `model.py:367-369` 里 μ、σ 是在 `(T, C)` 两个维度上算的（整块 patch 的统计量），
   而 `compressor.py:121-124` 是逐行沿列算的。两者数值接近，代码就这么用了，复现时
   需要留意。
3. **第一波段的解码器带一条“上一行同列像素”的跳连（论文没画）**
   论文 Alg. 1 写的是 `E_{y,x,0} = Decoder₀(û_{y,x,0}) − I^q_{y,x,0}`；代码实际是
   `pred = Decoder₀(û) + 上一行 band-0 的像素值`（`model.py:405-412`、
   `compressor.py:171-173`、`decompressor.py:177-179`）。也就是说，这个专用解码器
   学的其实是“相对上一行同列像素的增量”，属于 Sec. III-F 里 “spatial prediction
   only” 的具体实现。
4. **数据预处理与论文描述不同**
   论文 Sec. IV-A 说 “clips values between 0 and 10 000”；`dataset.py:43-45` 里裁剪被
   注释掉了，实际只用 `maximum_value = 1000` 做除法归一化。
5. **`mu/sigma` 与 `numerical warning` 的码率归属**
   `launcher_compress.sh` 统计的总字节数 = 残差压缩文件 + 数值告警文件 +
   `64*N_bands` + `mu.cmp` + `sigma.cmp`。而 `decompressor.py` 实际读取的是
   `side_info.h5` 里的浮点 μ/σ。也就是说，`*.h5` 本身没有计入码率，真正被计价的
   是 μ/σ 的**整数差分再熵编码**结果。若要严格复现端到端码率，需要自己把这块
   对齐（见 `05-压缩与解压.md` 第 6 节）。
6. **`model.py:482-532` 的 `generate_init_weight`、`trainer.py:70-111` 的
   `generate_init_weight` 是死代码**（引用了不存在的 `self.args`、`my_pile_stage`），
   从原 RWKV 仓库遗留下来，实际训练路径不会执行。
7. **`model.py` 与 `inference.py` 里有三套重复定义**：`LineEncoder/LineDecoder/
   BandZeroDecoder`（`inference.py` 版本多了“从 .pth 自动加载权重”），以及
   `RWKV_TimeMix/ChannelMix/Block/WKV`（`inference.py` 版本注释掉了 JIT）。
   `RWKV_ChannelMix/TimeMix/Block/WKV` 在 `inference.py:459` 之后的那一份是给
   `LineRWKV_RNN_spectral_parallel` 用的（并行谱预测走 CUDA kernel），
   `inference.py:121-456` 的两份纯手写递归实现则完全不用 CUDA。
8. **`ctx_len = 512` 同时写死在 `inference.py:546` 的 `T_MAX`**，CUDA 反向核里
   `F q[Tmax], r[Tmax]` 是栈数组，所以**训练时的行数上限被硬编码为 512**，
   超出会出问题。
